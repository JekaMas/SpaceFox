# Native SpaceFox source

The manifest declares the device targets in [supported devices](../docs/SUPPORTED_DEVICES.md). The primary source profile is Garmin SDK 9.3 with Java 11; exact SDK and profile hashes are in `toolchain-lock.json`. The production release exporter requires a clean Git worktree, the existing external signing key, and the exact previous public release receipt and IQ. The SDK and private keys are not shipped in Git. See [release handoff](../release/HANDOFF.md) and `python3 -B tools/release.py --help`. Native admission validates the source-bound software proof without a bypass. A successful compile is not physical, phone or Store acceptance.

For a simulator development build, install the official SDK and profiles, use Java 11, and provide a disposable development PKCS8 DER key outside Git. Set `SPACEFOX_SDK`, `SPACEFOX_JAVA` and `SPACEFOX_TEST_KEY`, then run `python3 -B tools/build_watchface.py`. Start Garmin's Connect IQ simulator and run the selected target's program with `monkeydo`. Development UUIDs are separate from the release identity. The [testing guide](../docs/TESTING_ON_PHONE.ru.md) describes model selection, settings and later USB/phone checks.

The four ACTIVE field positions preserve property IDs 0–5. The watch picker discovers accessible complication identifiers at runtime and checks public ActivityMonitor capabilities; it does not ship a per-model reading list. Some complication names resemble the established choices: both remain available because a complication is its own source, not a replacement for a legacy reader. The phone's static XML offers **Selected on watch** as value 6, which uses the last watch-selected identifier stored separately for that position. A missing provider or reading displays a dash without replacing the identifier. LOW and hidden states do not subscribe to selected fields.

Adding a model still requires the normal supported-device qualification: pin its official SDK profile, confirm API, permissions, font, round geometry and memory limits, add its manifest part, compile and inspect the exported IQ and model-specific PRG, and obtain appropriate native layout and resource evidence. Runtime discovery then exposes the model's accessible sources without a device-name branch; discovery alone does not qualify a model or establish physical behavior.
