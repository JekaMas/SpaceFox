# Installation and testing

For the current incident and released versions see [TESTING](../TESTING.md). The filename is retained for existing links; this guide is in English. The original Garmin app has 0.1.10 submitted and pending; the latest GitHub test build is 0.1.11 and has not been submitted to Garmin. Neither is an observed corrected physical installation or a Garmin Store approval.

The local PRG route tests the exact binary independently; it does not establish Garmin Store update delivery, and settings and cache survival are unknown. To try a signed test program on a watch, verify its checksum and model, connect the watch to a computer using a data cable, copy the matching `.prg` into `GARMIN/APPS` over USB/MTP, eject safely and select SpaceFox on the watch. Choose `fr165m` for Forerunner 165 Music and `fr165` for Forerunner 165. A phone cannot install a local `.prg` or `.iq` by tapping it; `.iq` is the developer export. Pairing through Garmin Connect supplies the normal communications path; pairing alone does not install that local file. Do not invent a `.SET` file or assume settings survive an install route change.

The clean default is English, with feed base `https://jekamas.github.io/SpaceFox`. On-watch settings include language, four metric choices and independent clock, countdown and field colors. For simulator use select the matching Garmin SDK profile and run its PRG with the SDK `monkeydo` executable; simulator output does not prove the behavior of a physical watch. The source uses the pinned SDK 9.3, Java 11 and signed SDK outputs; see [native setup](../watchface/README.md).

For a future readback record the exact checksum, executing version, watch model, phone/app and times. Check local date and 24-hour time, all four settings and six colors, unavailable metrics, active/AOD transitions and settings persistence. In a controlled simulator fixture, inspect T- at more than 24 hours and under 60 seconds, T+ at zero and through at least 15 minutes, and unknown, stale and rescheduled states. Local zero is not proof of launch. Observe real launch-data and separately changed asset revisions when available; disconnect and reconnect the phone and record cached offline display and actual refresh. Scheduling, phone delivery and physical behavior are separate evidence, not established by a compile or a request. Do not include private health values in a report.
