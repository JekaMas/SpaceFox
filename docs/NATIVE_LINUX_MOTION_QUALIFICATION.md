# Offline Linux motion qualification

The isolated job `qualify-native-linux-motion.yml` runs only on the named
`qualification/native-linux-motion` branch push or manual dispatch. It has
read-only contents permission, no provider/Pages/state/token inputs, and uses
the same exact package installer as the historic static qualification. It
checks an actual Ubuntu 24.04 AMD64 runner and the pinned renderer/package;
downloaded package cleanup is handled by the unchanged installer. It uploads
bounded diagnostics, including on failure. It is not enabled in the publisher.

The lock pins current G21 production modules, all catalog recipe inputs, the
literal fixture recipe, the actual complete Mac 2.57 references, tests and
workflow. The fixture rebuild uses existing local sources only. It exercises
NZ model / French operator / US site, flat and globe, A/timeline-B/image-B/A,
missing and shared country; source validation remains the original age.
Every actual legacy stream is rebuilt independently alongside motion and must
be byte-exact. The independent decoder checks every raw SFR pixel; all scene,
timeline, source and other file bytes must equal the pinned Mac reference.
Explicit literals enforce feed/object/transfer/raster/cache/artifact budgets,
including current/prior unions. Output contains bounded diagnostics, not a
publishable candidate. A mismatch or invalid reference refuses qualification.
Mac execution, even if exact, is not Linux evidence.

The old static lock remains unchanged and still refuses current owners: two
source modules differ. `tests/fixtures/native-linux-motion/static-archive`
contains all 16 original source files and the old qualification files at their
original relative coordinates, checked against the unchanged old lock. The portable packet carries those bytes
and the original static qualification inputs and reference separately; no old
execution receipt is rewritten or expanded. To execute that archived static
qualification separately, materialize its pinned old files over a separate clean
checkout before invoking its original driver, never overwrite this candidate.

Motion validation can re-render an origin during authenticated state reopen.
Publisher construction calls GitState.load → _files → snapshot admission →
`native_motion.validate_artifact` → `_raster`; arm also validates delivery
snapshots, and deploy and promotion/recovery reopen state. A future production
workflow must account for renderer availability in every job that actually
validates a motion snapshot, not only prepare. This document does not activate
or propose a production workflow. An SFR1-to-SFR1M change needs a higher
publisher generation because same-generation cache wire seals reject changes;
selection validation/source age must not be advanced solely for the profile.
Actual Linux run, separate whole review, public source publication, future
HTTPS/profile lifecycle and physical/SDK acceptance remain separate.
