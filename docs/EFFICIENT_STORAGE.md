# Storage design and historical format study

The publisher owns the canonical catalog; the watch receives only the selected launch and required definitions and assets. Model, organization and site identifiers occupy distinct namespaces. Deduplicate shared resources by digest without conflating identity. The persistent cache retains the accepted version and its required recovery closure while staging a candidate; enforce byte and entry limits, defer a candidate that cannot fit safely, and do not evict active resources to make room. Failed writes or interrupted activation must not destroy the working version. An actual source confirmation can advance source age without re-downloading unchanged artwork. Countdown redraws do not require storage or network I/O.

The publisher and visual root remain schema 3 `native-motion-v3` with SFR1M at `/feed.json`; the watch schedule is the separate trusted JSON projection at `/watch.json`; the historical format exploration below does not introduce a second supported profile. Preserve null, zero, unknown status, full IDs, UTF-8, time units and coordinate precision. The decoded UTF-8 schedule limit is 8192 bytes, including definitions and metadata; compression does not raise it or establish a RAM limit. The full publisher artifact budget is 1 MiB. Resolve any demonstrated retention/size conflict without silently dropping supported coverage. See [design](../openspec/changes/spacefox-watchface/design.md), [requirements](../openspec/changes/spacefox-watchface/specs/visual-catalog/spec.md) and [tasks](../openspec/changes/spacefox-watchface/tasks.md).

The saved study compared 839 historical catalog records: 103 countries, 170 configurations, 350 organizations and 216 sites. It did not refetch data. Readable JSON was 394,969 bytes (gzip 26,140); compact JSON 283,782 (gzip 24,495); column names once plus row arrays 137,596 (gzip 21,688). The reconstructed typed JSON tree matched, and gzip was round-tripped byte for byte. [Method, hashes and results](../openspec/changes/spacefox-watchface/evidence/efficient-storage/format-study.json) do not demonstrate FR165 memory or battery savings or justify sending the whole catalog to the watch.

Native qualification must measure transfer, decoded data, peak parse/activation memory, simultaneous graphics, persistent storage and redraw allocations under cold/warm cache, repeated data, changes, full storage, interruptions and reboot. Garmin's [Storage API](https://developer.garmin.com/connect-iq/api-docs/Toybox/Application/Storage.html), [resources](https://developer.garmin.com/connect-iq/articles/core-topics/Resources.html) and [Communications API](https://developer.garmin.com/connect-iq/api-docs/Toybox/Communications.html) describe API constraints; firmware support and device budgets must be verified for the target.
