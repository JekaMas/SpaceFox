# Свой SpaceFox: инструкция владельцу и агенту

Оригинальная инструкция и спецификация SpaceFox — [MIT](../LICENSE).
Основной вариант для одних часов: **GitHub Actions → статические файлы GitHub
Pages → Garmin Connect на телефоне → Forerunner 165**. AWS, собственный сервер,
домен, аккаунт SpaceFox и модель, вызываемая при каждом обновлении, не нужны.

**Состояние:** это согласованный план настройки. Сейчас в репозитории есть спека,
макет и переводы. Нативный циферблат, `tools/update_feed.py`, каталог/сборщик
графики и `.github/workflows/update-feed.yml` ещё предстоит реализовать по
[задачам](../openspec/changes/spacefox-watchface/tasks.md). Нельзя считать этот
документ уже работающим установщиком или считать будущий адрес данных активным.

## Как будут приходить обновления

1. Обычный скрипт в Actions запрашивает Launch Library 2 и проверяет ответ:
   обычно раз в час, а в окне от двух часов до известного старта до 30 минут
   после неподтверждённого времени — раз в 15 минут. Затем возвращается к часу;
   неизвестное время тоже проверяется раз в час. Это один или четыре основных
   запроса в час; дополнительные/ручные запросы расходуют тот же лимит 15 в час.
   Пятиминутный режим — отдельная настройка. При ошибке сохраняется рабочий кеш.
2. Скрипт публикует небольшой `data/v1/schedule.json` и согласованные статические
   каталог/изображения. В JSON остаются идентификаторы, время/точность, статус,
   ракета, компания, миссия, страна/площадка, координаты и возраст источника.
   Начальный предел JSON — 8 КиБ, после измерений на FR165 он может стать меньше.
3. Циферблат получает файл через Garmin Connect по той же часовой/15-минутной
   политике. Отсчёт считает сам: `UTC старта − текущий UTC часов`. После сна
   пересчитывает его по часам; постоянно работающий таймер не нужен. Время,
   перерисовка и локальная анимация не вызывают сетевых запросов.
4. Изменение времени того же запуска даёт `!` и янтарный отсчёт. Неизвестное
   время убирает точный отсчёт. Устаревший источник даёт отдельный знак; постоянной
   строки «обновлено…» на экране нет. Без телефона работают часы, поля и кеш.

Более редкие проверки означают более позднее обнаружение переноса, отмены или
нового запуска. Два независимых часовых опроса могут добавить почти два часа,
а 15-минутных — почти полчаса, затем добавляются задержки GitHub/CDN/связи.
Сам отсчёт продолжает идти точно относительно сохранённого времени старта.

Порог устаревания соответствует трём ожидаемым циклам издателя: три часа обычно,
45 минут перед стартом; при настройке другой частоты меняется и порог. Возраст
относится к источнику и конкретному сохранённому запуску. Старый JSON его не
обновляет. Уже выставленный признак устаревания не снимается только потому,
что частота снова уменьшилась: нужна новая проверка источника.

Ракеты и точки космодромов обновляются через тот же хост: исправить одну запись
каталога/положить разрешённую картинку, проверить, собрать новую ревизию и
опубликовать. Изображения и кадры имеют неизменяемые адреса с версией/хешем.
Часы активируют только целую проверенную версию; подготовку/сохранение графики
ещё нужно квалифицировать на FR165. Обновление картинки не требует правки layout.

## Что агент делает при настройке экземпляра

Эта последовательность применяется, когда владелец попросил реализовать/настроить
его экземпляр. Публикация одной спеки не включает расписание автоматически.

1. **Проверить исходники и инструменты.** Прочитать README, выбранные спеки и
   задачи. Если updater/workflow/циферблат ещё отсутствуют, сначала реализовать и
   проверить их в разрешённой задаче; сообщить о недоступных инструментах точно.
   Не устанавливать SDK или включать оплату незаметно.
2. **Выбрать репозиторий владельца.** Для текущей семьи — `JekaMas/SpaceFox`.
   Другим — их fork/копия MIT-проекта. Проверить владельца, публичность и рабочую
   ветку. Результат не должен зависеть от личных токенов/хостинга автора SpaceFox.
3. **Настроить стандартные Actions и Pages.** Workflow находится в default branch,
   запускается по расписанию и вручную. Для fork явно проверить, включены ли
   Actions. Базовый cron может просыпаться раз в 15 минут для дешёвой проверки
   срока следующего опроса; обычный provider-запрос и публикация выполняются
   только когда подошёл часовой/ближний срок. Это не запрос LL2 при каждом wakeup.
   Проверить и задокументировать эту разницу между wakeup и обновлением.
   Pages использует custom Actions artifact/deploy, а не сборку от
   каждого коммита. Обычный публичный runner; права сборки `contents: read`,
   публикации `pages: write`/`id-token: write`, среда `github-pages`.
   Административное включение Pages выполняется от имени владельца при настройке.
4. **Проверить квоту и сохранённое состояние.** Сериализовать запуски, учитывать
   ручные повторы и все provider-запросы, соблюдать backoff. Восстанавливать
   прошлую рабочую версию вне временного runner workspace; не считать Actions
   cache единственной копией. Не заменять отказ источника сгенерированными данными.
5. **Опубликовать и прочитать результат.** Запустить вручную, проверить настоящий
   HTTPS JSON и все ссылки на каталог/графику, потом дождаться следующей успешной
   проверки источника. Прочитать оба результата с публичного адреса, отличать
   время сборки от проверки провайдера. Начальный бюджет артефакта — 1 МиБ,
   retention — один день; не накапливать raw API-дампы и не расширять платные лимиты.
6. **Указать адрес в часах.** Использовать `FeedBaseUrl`, полученный от Pages
   именно этого репозитория. Пример будущего адреса текущей семьи:
   `https://jekamas.github.io/SpaceFox/`; файл — `data/v1/schedule.json`.
   Это пример до фактического включения Pages. Для fork/другого имени/домена адрес
   другой; его задают в настройках циферблата, не меняя компоновку или код списка ракет.
7. **Проверить телефон и часы.** Реальное получение на FR165, перезапуск с кешем,
   потерю связи, старый HTTP-200/304 файл, перенос/неизвестное время, исправление
   точки/картинки, ошибку частичной версии и восстановление. «Workflow зелёный»
   не доказывает получение данных часами. Сохранить версию прошивки и наблюдения.

В обычном анонимном режиме API-ключ не нужен. Если конкретному владельцу позже
понадобится свой ключ, хранить его в GitHub Secrets и отдельно проверить квоты.
Он не попадает в настройки часов, JSON, артефакты или исходники. Данные здоровья
и сведения о ребёнке не отправляются в этот публичный feed.

## Если обновление остановилось

- Часы продолжают отсчёт по сохранённым данным и показывают старение источника.
  Значок переноса сохраняется независимо. Ноль не подтверждает реальный взлёт.
- Проверить подключение телефона, возраст **источника** в JSON и последние
  Actions/deployment-запуски. Старый файл может всё ещё успешно открываться.
- GitHub может задерживать/пропускать cron и отключает расписание публичного
  репозитория после 60 дней без активности. Запуски сами по себе не следует
  считать достаточной активностью. Проверить состояние, при необходимости
  включить workflow снова, запустить вручную и подтвердить новый файл и приём часами.
- Не обновлять timestamp, чтобы спрятать сбой, не переключаться автоматически
  на чужой feed и не обходить ограничения новым runner/IP. После восстановления
  свежесть снимается только по настоящему подтверждённому времени источника.

Агент может обслуживать эту схему. Если позже потребуется запускать updater на
своём компьютере, тот же обычный скрипт можно вызывать локальным планировщиком;
тогда компьютер должен быть включён и иметь сеть. Одновременно двух издателей
для одного экземпляра не включать без общей сериализации и бюджета запросов.

## Готовое поручение другому агенту

> Подготовь личный SpaceFox для моего Garmin Forerunner 165 по MIT-спеке этого
> репозитория и docs/AGENT_SETUP.md. Используй мой GitHub fork, стандартные
> GitHub Actions и статический GitHub Pages feed. Сначала проверь наличие и
> реализацию updater/workflow/циферблата; отсутствующее нельзя выдать за готовое.
> Настрой мой FeedBaseUrl, квоты, источник свежести, кеш и восстановление.
> AWS, отдельный сервер и регулярные LLM-вызовы не нужны. Не включай оплату и не
> передавай личные токены автора или данные здоровья. Проверь публичные файлы и
> фактический приём часами, сохрани результаты и укажи точные оставшиеся ограничения.
