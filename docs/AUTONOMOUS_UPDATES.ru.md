# Autonomous updates

The configured chain is Cloudflare Cron (`7,22,37,52 * * * *` UTC) → GitHub-hosted Actions → GitHub Pages. The publisher reads the upstream schedule when due, validates and publishes a consistent static data set; the watch counts seconds locally. It needs no running Mac, agent, AWS or regular LLM calls. Feed updates do not update watch-face code. Services and the upstream provider must remain available, and delivery to a watch also depends on its phone and connectivity.

On 13 November 2026, two natural scheduled runs, [43433017023](https://github.com/JekaMas/SpaceFox/actions/runs/43433017023) and [43442034551](https://github.com/JekaMas/SpaceFox/actions/runs/43442034551), completed on GitHub-hosted Ubuntu. The [hosted evidence](../openspec/changes/spacefox-watchface/evidence/autonomous-updates-20261113/) records the observations and their limits. A separate local official simulator observation loaded and reopened hosted data; see [its result](../openspec/changes/spacefox-watchface/evidence/local-autonomous-delivery-20261113/RESULT.json) and [in-place update](../openspec/changes/spacefox-watchface/evidence/local-autonomous-delivery-20261113/INPLACE-RESULT.json). Those observations do not establish physical phone-to-watch delivery. The Mac was not literally powered off during the test; independence follows from the observed remote configuration and execution, within that evidence's scope.

Normal updates do not require continuous agent monitoring. The recorded restricted GitHub dispatch token expires on 12 November 2027; replace it in the same Cloudflare encrypted secret before expiry, subject to current account configuration. The recorded token grants Actions write and Metadata read only for SpaceFox; do not place its value in source or logs. A missed invocation can be retried on the next scheduled event, using durable state for recovery; a successful dispatch alone is not proof of publication. Availability depends on Cloudflare, GitHub, the upstream source and phone connectivity. Operator setup, maintenance and recovery are documented in [CLOUD_DELIVERY](CLOUD_DELIVERY.md). The observations above do not establish future unattended operation or physical delivery.
