# Decoder timing hypotheses

Observed: the controlled retained Cape map decoder required 401 50 ms callbacks and 20,064 ms. This is a decoder proxy, not direct cache-to-ready timing. Three scheduling-only trials failed to meet both timing and watchdog bounds; see receipt.json. The requested full-scene oracle requires a NativeSfrRenderer with non-null mapBitmap and matching selection hash after the build and closure complete. The bundled LOW image may draw earlier and is not by itself that predicate.

Hypothesis A: per-pixel outline construction dominates CPU and prevents safe row batching. Prediction: instrumented elapsed CPU for draw/outline greatly exceeds RLE decode and hashing. The current production decoder uses the RGB row buffer directly; it does not call Graphics.getPixel. Controlled FR165 instrumentation measured 4,758 ms in draw/outline, 612 ms in decode/paint, and 13 ms in hashing across 390 rows. This supports A, subject to instrumentation overhead; it does not by itself prove a full-scene deadline.

Hypothesis B: when the exact current qualified bundled outline is available, decoding its separate dynamic outline is redundant for the rendered LOW output. Prediction: retaining the same qualifying point, pin placement and bundled bitmap while avoiding only fallback extraction preserves the visible output and permits short bounded batches. Confirmed for the retained Cape scene by a 5703 ms ordinary no-push completion and byte-identical controlled LOW captures; future unmatched points must retain the decoded fallback and digest checks. No production change is accepted on the basis of this hypothesis alone.

Harness: the initial full-scene seed was refused because its test clock preceded the retained feed validation time. A corrected seed reached 19 objects on the ordinary 126,784-byte profile; its attempted cross-process reinstall did not preserve the intended seed. Both are setup observations, not product timing evidence. A same-process production view/cache reload observer is being evaluated.

The streamed RGB repair holds one authenticated shard and decodes canonical 128-character blocks; the matched bundled path avoids the redundant dynamic outline. An ordinary two-process FR165 observer completed all roles and closure in 5703 ms at 126784 bytes. The test-key program adds only match/timing observations to the current view; it is not a production-signed runtime or physical performance result. Earlier SDK failures and diagnostics are retained.
