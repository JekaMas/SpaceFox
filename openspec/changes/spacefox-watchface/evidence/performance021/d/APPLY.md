## IO-01 event contract before implementation

A batch instance is event-local. Domain events are: select/begin a closure; receive one requested valid object; receive corrupt bytes; complete a closure; replace the closure; and begin a new event with the same durable store. The independent expected sequence is the ordered list of still-missing fixture refs, with the accepted scene/seal unchanged on corruption. Each valid receive is applied; corruption is observed without the object being admitted; changing source or restarting starts a fresh verification scan. Counters observe object-store reads/hash work through the actual `NativeBatch`/`NativeImmutable` boundary; expected counts are derived from literal fixture identities and event order, not an internal cursor. Completion must preserve the separate full closure digest/admission and pins, and a later scan must detect newly corrupt/missing bytes. Cases need directed transitions and replayable failure receipts before this finding can be marked green.
