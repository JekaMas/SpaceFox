# Current SFR1M directed SDK observations

`raw/` records Linux SDK 9.3 / FR165 API 5.2 compiled diagnostics and their exact inputs, output and source/resource bindings. The ordinary A/B probe inserts selected producer objects through `NativeImmutable`, admits their feed through `NativeCache`, prepares three native bitmaps, then reopens by `openApp(push=false)` in distinct simulator processes. Its probe writes its own stage marker after asserting zero `NativeStore` writes, so the DAT/IDX files differ; these are not read-only whole-store or physical reboot claims. The B data is a technical mutation of the captured A selection.

The ordinary animated probe uses a controlled nativeMotion mutation on the real captured Starship art and tests native interpolation and one heap sample. It reports 90,152 used of 126,784 bytes at one instant; this is not an allocator or GFX peak. `tests.test_sfr1m_current_animation` separately runs the actual current producer and compares all decoded pixels with an independent literal SFR1 decoder and fixed reference digest. The catalog mutation is a test input, not a published or newly researched artwork.

The direct `receiveBatch` probe uses actual native cache and SDK Storage, controlled response and callback completion. Its old assertion for diagnostic telemetry failed because that telemetry was removed in current production; the failed run and original build are retained. The repaired probe asserts no success continuation, rejection, prior pointer, B context and subsequent retry/recovery. The exact unknown-operation negative rehashes the modified current raster descriptor and scene; it uses a unit-test store. Framework exit 1 is interpreted only alongside its complete named 2/2 table. Ordinary runs with exit 143 were terminated after explicit markers; the first empty animated and callback launcher attempts have no completion observation.

`python3 -B -m unittest -v tests.test_sfr1m_current_receipts tests.test_sfr1m_current_animation` verifies source/resource/probe/receipt bindings and runs the producer control. It does not run the SDK. The sourceHead/actualBase strings within build records are explicitly substituted historical diagnostic values, not Git provenance. Natural firmware dispatch, actual HTTPS/phone, physical power loss, true transient or GFX peaks, and Store acceptance are not established. The independently retained P3 raw-feed callback and other cache properties have their own boundaries; the 8 MiB SDK test heap cannot be substituted for ordinary service memory.
