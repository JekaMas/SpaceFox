# Published signed 0.1.14: bounded simulator observation

**Author self-check: GREEN for this one simulator scenario; independent review pending.** On 2026-11-15 an isolated SDK 9.3 simulator used the FR165 profile (126,784-byte reported heap), no network, no host ports and a historical public Cape/Vulcan cache. The original production-signed `/assets/SpaceFox-fr165.prg` was loaded with Garmin's normal `monkeydo` command, immediately after SHA-256 verification of `37ea2195c445d6b82a009f6aaf5a32b0571ab3b2f3d043dd7d80073461eb2d73`; the running loader process recorded that same input path. The signed PRG was not rebuilt, patched, or re-signed. Previously verified release signature and identity evidence applies independently.

## Negative control and sequence

1. A diagnostic watch-face seeder with the production UUID and signing identity, version 0.1.13, used its only initial view to display **SEED ONLY**. Its retained [source](seed/SpaceFoxApp.mc.txt) shows that this view only clears the display, draws that label, and runs the seed routine: it cannot render the production face. [Control image](control-seed.png); [seed log](control-seed-run.log) records 19 objects and the profile heap. The diagnostic PRG SHA-256 is `3661d34915c762e17ce7ae1ba811a11ab2b57caeac9c02aaf076ee3fd7af1e67`; it was compiled from this source and retained harness inputs, with ordinary source owners and the previous generated version file. It is not the released program. The local diagnostic binary is retained for the independent review; no signing material is retained here.
2. Without restarting the simulator, changing volume, copying DAT/IDX, or changing the default feed namespace, the diagnostic loader was stopped and the normal SDK `monkeydo /assets/SpaceFox-fr165.prg fr165` loaded the actual release input. [Input hash and frame times](control-load.log); [running loader command](control-loader-process.log); [bounded stop record](control-stop.log). Garmin’s SDK command-line setup documentation and [developer forum discussion](https://forums.garmin.com/developer/connect-iq/f/discussion/317485/can-the-simulator/1540968) describe monkeydo as pushing and running a Connect IQ executable and [application Storage as persisting across executions](https://developer.garmin.com/connect-iq/articles/core-topics/Persisting_Data.html). The seed-only control, normal loader and observed production view together establish the input-to-scene association without assuming the SDK's host MEDIA blob is plaintext or claiming its encoding.
3. The [first ACTIVE frame](control-actual-a.png) at 15:09:46 UTC shows Vulcan VC6L, ULA, Cape Canaveral SFS, the US flag, rocket, map, marker and four simulated fields. [LOW](control-actual-low.png) at 15:10:17 shows the map outline, large clock and minute-resolution T+. [Later ACTIVE frames](control-actual-b.png) at 15:10:31 and [15:10:42](control-actual-c.png) show coherent restored scene and advancing seconds. The loader was still running at 15:11:03, 98 seconds after the recorded start, and was manually stopped. [Runtime output](control-actual-run.log) was empty: no exception or watchdog report was observed in this bounded run.

## Fixture and limits

The 19 seed JSON objects and feed in [seed/resources](seed/resources/) were checked byte-for-byte against the already tracked [public fixture](../site-flag-visual-batch/native-artifact/); [fixture check](fixture-check.json) records their individual hashes. They represent retained public historical data, not a live provider fetch. The feed's nominal launch time was 2026-11-13 17:54 UTC. The simulator clock was not adjusted; T+ reflects that historical target at the actual observed simulator time. All health values were simulator values. Screenshot coordinates and display modes belong to the simulator, not a physical watch.

This single English, offline, ordinary-profile observation does not establish natural networking, a new feed generation, phone behavior, physical display or battery behavior, real health data, full memory peaks, Store acceptance, or completion of the wider property graph. The earlier [failed attempts](ATTEMPT.md) remain diagnostic and do not weaken this receipt. The SDK and task-owned container were stopped after the observation; no other simulator was touched.
