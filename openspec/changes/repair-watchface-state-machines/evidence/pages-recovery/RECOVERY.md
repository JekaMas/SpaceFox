# Autonomous Pages stale-intent recovery

The first 0.2.6 main push triggered workflow run 44034592095, which failed in prepare: Pages returned an empty status for a retained armed intent. The public watch snapshot was still generation 70. The same condition affected multiple earlier scheduled or dispatch runs; none is called successful here.

The durable armed intent is generation 71, originating from source `834ef3177da535b09cf70dad7d786cb0aab5a367`, run 43991076329 attempt 1. GitHub's run/job metadata shows its deploy step failed. Its job log records the specific `queued source code is stale before work permission` error inside that step and exit code 2. The originating source's deploy/main/context and Pages request/finality control functions have the same AST as the current reviewed implementation: that error is raised before the Pages POST. The Pages status for that build remains empty. An actual read-only `never_started` evaluation against the historical GitHub run returned true after these bounds were applied. A first evaluation incorrectly rejected the witness because GitHub truncates step completion timestamps to whole seconds while log entries carry fractions; the corrected bound includes only that last second.

`never_started` now accepts that specific failed-pre-POST witness in addition to its existing skipped job/step proof. It verifies exact run/repository/source/attempt/job/step identity, bounded log output and timestamp, one error, and unchanged critical source control-flow AST. A changed function, missing/duplicate log, mismatched identity, unbounded output, missing API result or other failure stays armed; no guessed retry or manual journal reset is permitted. Actual POST/finality remains separately required for a later deployment.

`first-red.log` preserves the local failing regression. `focused-green.log` records the new positive/negative test and the existing empty-status/skipped-witness test passing. `existing-first-error.log` preserves an unrelated test adapter error: replacing the entire cloud time module left monotonic as a mock. The targeted adapter now delegates monotonic to the real clock while still mocking sleep; no production time behavior changed. The native 0.2.6 binary is built from the earlier frozen tag and is unaffected by this host-only repair. Successful deployment and public readback are recorded separately after observation.
