## Fakes, isolation and limits

Each worker/trace has a distinct in-memory Git realm, refs/object database/index, deterministic entropy namespace, fake ports, model and counters. `MemoryGit` only replaces Git transport/object reads; inherited production bootstrap/load/write/transition validation/CAS construction execute. There are no business temporary files or real Git subprocesses. CAS success/failure and source movement are controlled domain events. The source-after-save event changes only the fake authority at the commit boundary and exercises the real post-save permission check.

Captured immutable bytes in `tests/fixtures/current_authority/frozen-current.zip` are loaded once as harness input before any business scope. The fake product service reuses these pixels/roles and creates a feed envelope from supplied inputs. Actual wire/Publisher generation, source identity, pending hash and durable transitions execute. Graphics/source-graph rendering validation is replaced at its declared product port; this PBT does **not** qualify a real renderer, live provider or complete rendered artifacts. Fixture parsing/projection constructs inputs only. Expected source state/candidate values use separate model dataclasses/serialization; no expected state is copied from SUT output. The fixture has no mutable worker-shared state.

All SUT construction and domain events execute inside a thread-local business scope. Globally installed wrappers dispatch by that scope; they guard real wall/monotonic clock and sleep, entropy, file opens/mutations, subprocesses, sockets and thread/timer start. A forbidden-call counter increments **before** throwing and is asserted after every event, even if a SUT catches the exception. Negative controls verify this. No business clock/timer/network/storage/provider runs in short tests or planned campaigns. Real monotonic is used only by the outer coordinator for wall-duration/progress; fixture loading and trace/log IO are harness control work outside SUT scope. Python threads have independent state and observed overlap; CPython/GIL does not imply parallel CPU execution.
