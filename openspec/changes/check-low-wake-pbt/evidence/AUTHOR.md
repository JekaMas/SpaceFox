# LOW-to-ACTIVE PBT adequacy: author report

Base: public main `4ee218f70a5e3a1e1a543deb32a950e969fca767`, product version 0.2.11 / NativeID `3c4d93d0`. No production source changed. Physical wake dispatch and tap latency remain unobserved.

## Historical cause and invalidated claim

In `v0.2.10`, `SpaceFoxView.onShow` calls `lifecycle.show()`, observes OS LOW and leaves `sleeping=false`; its `onExitSleep` immediately returned when `lifecycle.wake()` returned false. Therefore a first OS HIGH wake without an earlier `onEnterSleep` failed to reconcile HIGH and request the ACTIVE frame.

The `v0.2.10` `ViewTrace` did call real view callbacks, generated eight event classes, and checked its model after each event and at end. Its fixed coverage prefix preceded 12–36 seed-driven event choices. However, an OS-mode event both changed `fakeMode` and called `view.syncDisplayMode` directly, before any callback. Separately the oracle called its own `sync` on wake only when the model's `sleeping` was true. The external OS change was therefore not independent, and the false-sleep wake expectation mirrored the faulty guard. The event sequence could be listed but its real boundary condition was not represented: the test had already forced the view to HIGH. `onShow`, `onHide`, sleep, wake, draw and timers were actual calls to the view seam, not merely the lifecycle reducer; their other observed assertions remain bounded by that model. Old campaign PASS receipts remain authentic historical results but do **not** prove this first-wake property. The 0.2.9 view campaign reported 63,200 traces / 3,286,403 events / 606.174 productive seconds; duration and count did not remedy the missing distinction. No new ten-minute result is claimed.

## Repair and evidence

`ViewTrace` now changes fake OS HIGH/LOW without invoking a view method, and calls `sync` in the independent reference model when the corresponding real callback or frame is dispatched. Its model begins hidden, awake and OS HIGH. A directed prefix tests OS LOW → `onShow` → OS HIGH → `onExitSleep` without `onEnterSleep`, then `onUpdate`; seeded tails vary the eight event classes and ordering. It asserts state and effect counters after every event and at trace end. Required per-seed disposition counts are asserted nonzero; a missing timer is counted as skipped, never as an observed timer no-op. `onShow`, `onHide`, `onEnterSleep`, `onExitSleep`, `onUpdate`, duplicate and hidden callbacks remain production calls. Fake clock, OS mode, frame requests, timers, presentation, layout, fitness and paint ports are installed before events; `PbtApp` has no normal app startup and no real network, storage, sleep or timer scheduling is used. Layout and paint are fake observations, not pixels.

Expected ACTIVE and one frame request; actual stayed LOW with zero requests. `historical-guard-red.log` retains the first run before the disposition-label refinement. The first failed setup logs and the first current-source coverage failure (`timer_applied=0`) are preserved; the latter was fixed by addressing the live timer in the witness, rather than narrowing its assertion.

## Replay and boundaries

The existing Monkey C suite uses `OwnerRandom` seeded with 1–32, a fixed causal prefix and variable-length pseudo-random tails; it is not exhaustive arbitrary-sequence proof. Event codes in the minimal replay are 0 show, 1 hide, 2 enter sleep, 3 exit sleep, 4 external OS HIGH/LOW toggle, 5 logical time advance, 6 frame, 7 fake timer fire. The patch and complete logs contain actual expected/observed state and counters. Reproduce using the existing SDK 9.3 Docker image and a private isolated task directory: compile `watchface/source` plus `watchface/stm-property-tests` with entry `PbtApp`, `-d fr165m -t -l 3`, then select `generatedViewLifecycle`, `firstLowWakeWithoutSleep`, and `offWakeDoesNotPaint`. For mutation, use an isolated copy of `watchface/source` with the recorded patch, not the production checkout, and run the same generator selector. A task-owned container with no network and its own simulator/data was stopped after the run. No other owners, 19 PBT campaigns, language checks, releases, or physical devices were rerun.
