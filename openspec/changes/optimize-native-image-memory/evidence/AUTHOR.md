## Decisions and ownership

* `NativeSfrBuild` already decides whether the accepted model uses bundled or remote rocket art. `NativeSfrDecoder` now verifies the bundled-rocket case without allocating a drawable bitmap or DC; it still reads and validates the immutable shard, byte length, bounded row grammar and complete RGBA pixel digest. The decoder retains necessary row/hash buffers: this is not a claim of zero heap allocation. Remote rocket and map paths still create their needed drawables. Raw old-source assertion RED, current GREEN, and the initial fixture-error attempt are retained as `rocket-allocation-red.log`, `rocket-allocation-green.log`, and `rocket-fixture-first-failure.log`.
* `tools/build_bundled_models.py` generates 184 cropped resources and offsets from the existing canonical SVG/catalog. It retains original color values even in transparent pixels. The independent original-source reconstruction is byte-for-byte RGBA identical for all 184; no second full source PNG collection is introduced. `SceneRenderer` applies the generated offset once per selected model. The actual renderer's LM2D frame origin is `(42,120)` for a 54×124 original canvas, and the selected Falcon Heavy resource is 22×120. Original fixed-canvas assertion failures and the two profile-specific current results are retained.
* A whole FR165M program compiled with Mac SDK 9.3 was 8,727,052 bytes at the original source and 7,910,780 bytes for this candidate, including anchor and decoder code: −816,272 bytes (−9.35%). The isolated 184-resource PRG was 1,362,844 versus 544,732 bytes, −818,112 bytes (−60.0%). These are compiled sizes, not graphics-pool peaks. The full program has version/source changes in addition to asset representation. Original SVG source and producer identity remain intact.
* The palette trial did not demonstrate an improvement in compiled size or app-heap allocation and did not establish the full marker/partial-alpha boundary. It was rejected. The changing-countdown outline bitmap trial was slower in one simulator microbenchmark and added another graphics owner; it was rejected. Both experiments, complete diagnostic source and retained raw outcomes are in `probes/` and this directory; neither changes production.
* `SceneRenderer.useDownloaded` already drops the superseded bundled rocket bitmap when a selected downloaded bitmap owns the scene; foreground admission already releases the old optional renderer and bitmap before loading the next snapshot. The verified-only decode removes another unnecessary bitmap owner. We did not infer precise graphics-pool bytes from app-heap samples.
