# Watchdog and callback inventory

The raw device reports remain local. Production 0.1.18 debug addresses associate the repeated device stacks with the foreground hash/admission path, but the installed PRG could not be read over MTP. StoreVersion 11 and the owner preview associate the reports with 0.1.18; they do not prove the installed binary's exact bytes. The captured real feed is 5,660 bytes. The pre-change 191 ms parser-owner measurement includes its owner callbacks and hashes, and is not a pure JSON or device-time measurement.

| Current caller | Work, bound and status |
|---|---|
| `getInitialView` / `restoreFeed` → `NativeRestoreJob` | Fallback frame precedes strict commit/recovery reconstruction. At most 16 stored chunks and 8,192 UTF-8 bytes; read, digest, parse, validation and inverse witness advance in foreground callbacks, preserving the prior seal. The real captured-feed strict reopen passes on FR165M. |
| `resumeAfterFrame`, `onBackgroundData`, settings → `NativeIncomingReadJob` → `NativePreparedBridgeFeed` → `NativeFeedPromotion` | Each parser call has 16 grammar/lexical operations (string scan at most 128 characters per operation), hash work is at most four 128-character slices, and storage promotion advances by chunk. The scheduler groups at most four steps, checks 12 ms between them and yields after releasing parser input. The final captured-input native test reports maximum 18 ms for an indivisible preparation step; simulator timing is not a physical guarantee. Complete rejected input is cooled for 300 seconds; unavailable catalog is deferred and retried on a background event or after the bounded delay. |
| LOW/wake and admission failure | The same job and marker survive LOW. The exact-time fixture displays consecutive countdown seconds while preparing. An invalid cache and a malformed complete feed both terminate in the actual simulator event loop with clock draws; rejection token/cooldown readback passes. An unexpected outer error drops the parser and timers and records an event-triggered strict restore instead of using a detached prior as a full packet. |
| `FeedService.receive` → `NativeTransfer.stage`, `NativeBatch.begin` | Network callback input is capped at 8,192 bytes and 16 parts; per-object input at 4,096 bytes, and batch at 40 references. Background context cannot use foreground Timer continuations. These input/work caps do not themselves establish a physical callback deadline. |
| `FeedService.receiveBatch` → `NativeImmutable.put` → `NativeBatch.next` | A prefix already verified in this service event is reused, and a fresh full closure scan precedes completion; corruption causes redownload. Captured 27-object whole callback maximum was 26 ms on the final simulator run. Largest allowed closure is finite but its physical latency is not established. |
| `prepareVisual` → `NativeSfrBuild` / `NativeSfrReadJob` / decoder | Descriptor and index hash/parse use bounded continuations. Decode/closure retain their finite row/object budgets and elapsed checks; each individual row/object operation remains indivisible. Captured 27-object scene's whole-step maximum was 24 ms in the final simulator run, including decoder work; other earlier simulator runs reached 66 ms. Cancel/failure releases read/parser owner cycles. |
| `onLayout` → `SceneRenderer.prepare` | Optional renderer, fonts, decoded resources, scene build and fitness are released or suppressed while input is resident. The 54 bundled map metadata objects are now constructed one at a time, preserving exact coordinates/resources and selection order. This addresses the observed FR165M warm heap failure; simulator screenshots and stock-digest readback do not prove a physical memory peak. |
| `LaunchReminder.wakeWith` / `syncEnable` → `sameIncoming` | A single uncached comparison can synchronously reconstruct and parse a feed capped at 4,096 bytes, followed by a semantic digest; the same-token result is cached. Whole wake with the retained 2,719-byte exact-time feed, including final recheck, measured 68 ms in the simulator. No general wall-time or physical-watchdog margin is inferred. |
| `NativeWireHash`, `NativeJson`, other current callers | Input, parser depth (8) and node count (5,000) limits remain enforced. Foreground feed and scene descriptor paths use continuations; legitimate background/reminder synchronous users retain their applicable caps. Other API calls may be indivisible. |

Garmin's [Timer API context list](https://developer.garmin.com/connect-iq/api-docs/Toybox/Timer.html) includes WatchFace and does not list Background. [Background execution](https://developer.garmin.com/connect-iq/articles/core-topics/Backgrounding.html) can terminate, has a 30-second automatic limit and a smaller heap. The above simulator results are software evidence, not a hardware acceptance or universal deadline proof.
