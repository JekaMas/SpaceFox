# FR165 graphics resource ledger

Scope: B1 source based on d1263b3799eaed9304b68e3508c278a49e39a88c, plus the provider-icon admission change; Linux SDK 9.3.0, FR165 profile `simulator.json` SHA-256 `c4e771539f1ccc68f1464ced980cd493d57d0cd8e46fa9e844ada36df9631fee`, `graphicsResourcePoolSize` 2,097,152 bytes. This is the simulator profile, not a physical measurement.

The [Garmin Graphics Pool documentation](https://developer.garmin.com/connect-iq/core-topics/graphics/) and the SDK's bundled `doc/docs/Core_Topics/Graphics.html`, section “Graphics Pool”, says resource references may be cached, unloaded and reloaded as available memory changes; a resource obtained via `ResourceReference.get()` remains locked while its returned object is in scope. `doc/Toybox/WatchUi.html`, `loadResource`, specifies BitmapReference and FontReference from CIQ 4.0 onward. The source's only graphics `.get()` calls are the SFR decoder buffers and a scale buffer that `SpaceFoxView.onLayout` allocates only if the display differs from 390×390; the FR165 profile is 390×390. `WatchUi.loadResource` in `SceneRenderer` and `SpaceFoxView` retains references, not explicitly dereferenced pinned bitmaps or fonts. System vector fonts are a separate owner; their internal memory is not given by this model. Provider icons are accepted only as managed BitmapReference objects at most 96×96; unsupported, oversized or failing icons receive a neutral marker without changing field values. Four 96×96 four-byte-per-pixel images add at most 147,456 bytes of payload to the conservative comparison. Normal safe icons are retained; a later refresh re-evaluates the provider icon.

For scale comparison, PNG IHDR dimensions of the largest referenced bundled mask (391×391) and AOD map (390×390) give 611,524 and 608,400 bytes respectively at four bytes per pixel; the largest requested bitmap-font atlas is 512×256 or 524,288 bytes. Allowing the two largest bundled bitmaps alongside the maximum pinned SFR payload gives 1,876,348 bytes, 220,804 below the profile limit before allocator, vector-font and other native overhead. This is a conditional working-set calculation, not a proven total peak: the SDK does not document a strict two-resource residency limit or overhead ceiling. Adding the maximum four admitted 96×96 provider-icon payloads yields 2,023,804 bytes, 73,348 below the profile limit before native overhead. This assumes the documented eviction behavior and the stated two-resource working set; it is not a measurement of total pool peak. `Complications.getIcon()` may return an externally supplied `BitmapResource` or `BitmapReference`: only the latter, bounded by the admission rule, is retained. An unavailable, unsupported, oversized or failed icon uses the fallback marker. The ordinary HIGH/LOW observations above supply direct evidence for their captured scene, not for every combination of provider, SFR role and AOD resource.

No claim is made that the two-copy native Storage read reserve is a universal amplification bound. Its exact 4,028-byte read / 8,184-byte-free failure and successful repaired ordinary path remain separately documented in `VERIFICATION.md` and `PROGRESS.md`.
