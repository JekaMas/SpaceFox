## First focused failures and hypotheses

The initial two native cases have retained RED tables in `evidence/sdk-freshness-red.log` and `evidence/sdk-reminder-red.log`. The first repeated a draw while the test view remained in default LOW and within the same minute; the LOW minute guard can return before the second freshness assertion. The discriminator is an explicit HIGH display transition with the same production draw owner. The second used the real exact fixture long after its original source validation; its reminder must be stale and suppressed. The discriminator uses the real fixture with a controlled technical target 960 seconds after its original validation while leaving the source age and eligibility guard active. These are harness hypotheses, not product or device proof; the rerun must establish their result.

The HIGH-mode discriminator advanced the first two cases but its rollover assertion failed (`sdk-freshness-red2.log`); all three rollover assertions originally shared one source line. Independent age arithmetic shows the chosen successor age was only 1900 seconds, below its 2700-second near threshold, so an expected-stale assertion was invalid. The corrected technical successor has a 997000 source validation, fresh at the alternate-context check and stale after the 1000900 rollover. Assertions are separated. The reminder discriminator passed with the original validation age and controlled technical target.

## Bounded decisions A01, A07 and A06

A01/A07 are retained by design, not labeled runtime defects: the current decode/clock fallback rebuilds bounded packed coordinates and world segments per eligible frame; the renderer's persistent alternative has a different lifetime. The current integration peer retained paged packed world geometry to preserve the optional-SFR resource margin. The actual source reserve is phase-sensitive: a 4,028-byte shard read previously failed with 8,184 bytes free, so the current owner reserves two shard copies plus bounded row/decode/clock work (or 8,192 bytes for an already-owned descriptor continuation). This is historical source/SDK evidence, not a physical peak, frame-time, speed or battery measurement. A small selected-ID/point cache was considered but has no demonstrated equal-heap bound or lifecycle/context invalidation proof; keeping frame-local geometry avoids adding retained arrays and does not assert it is optimal. Reconsider only with a concrete same-budget measured witness.

A06 retires only the old flat reminder snapshot read. A flat or malformed snapshot now fails closed; no old eligibility, precision or time is invented. The active writer continues to publish bounded current rows, preserves `since` for matching current rows and retains the separately stored consumed-slot ledger. The ledger is neither cleared nor rewritten on unknown snapshot, and a fresh accepted current snapshot is needed before any eligible reminder resumes. This may suppress an old unsupported pending reminder until current admission; it does not generate catch-up notifications or erase consumed current slots. There is no observation that any current device held the old shape, and no migration layer is introduced.
