# Visual evidence reuse after snapshot-write repair

The EN/RU menu and ordinary ACTIVE/LOW scene images were captured on the immediately preceding 0.1.15 native source. The subsequent repair changed only `LaunchReminderForeground.publish`: it skips writing an identical reminder snapshot and avoids deleting a missing snapshot; `NativeVersion.ID` consequently changed. The exact pre-repair bytes of those two native files, reconstructed against their pre-repair source hashes, are retained beside this note. BUILD remains 0.1.15 and the menu title uses BUILD, not ID. The [EN](Host-en.mc.txt) and [RU](Host-ru.mc.txt) host entry points directly return `SettingsMenu.root` and do not call the changed foreground publisher. Menu strings, fonts, renderer, settings UI and all other native source/resource inputs are unchanged by this repair. Thus the earlier visual observations remain applicable to those visual claims; they are not a fresh execution or heap measurement of the repaired build. The current binary and focused snapshot-write cases are separately compiled and tested.
