## Finding and repair

The prior host guard checked the committed predecessor version and IQ digest but did not enforce the recorded receipt digest or compiled source revision. A controlled negative using the actual 0.1.15 IQ and a modified receipt with the same version, UUID and key, but a different `source_revision`, unexpectedly reached the pre-export boundary. The initial regression failed with `ExportBoundaryReached`; no export or key operation was performed. The repaired production guard now also compares the retained receipt's source revision against the policy's **compiled source** and verifies the exact original receipt bytes. It retains the existing IQ, version, UUID and key checks. An altered receipt with unchanged source and package is also refused. The installation handoff explains that reformatting the receipt changes its digest. This is a host release-tool change for future candidates, not a modification to the already published binary, receipt, ZIP or checksum files.
