# Ordinary background observation

In an isolated network-none Linux SDK9.3 FR165 simulator, a disposable watch-face identity staged a real-format typed-operator fixture with a controlled source-validation-only refresh, registered an immediate temporal event and ran the actual `LaunchReminder.sameIncoming` in `ServiceDelegate.onTemporalEvent`. The [probe source](Probe.mc.txt), [compile log](compile.log) and [run log](run.log) retain the controlled boundary. It reported `same=true`, `usedBefore=32224`, `usedAfter=33792`; these samples are not a measured peak or physical memory result.

A controlled quiet input consumed a slot without a notification call. An unquiet second identity returned from the real system notification API once; a duplicate produced no second return marker. A third identity deliberately threw a notification-boundary exception; the SDK printed an `Unhandled Exception` diagnostic stack, after which the service continued to `BG_PROBE_EXCEPTION_CONSUMED` and completion, with no second notification marker. This is an intentionally injected exception, not a clean-error-free observation. Sleep/quiet inputs were controlled here; the separate [quiet-field probe](../quiet-probe/RESULT.md) records simulator field types. No physical alert or vibration was observed. The launcher was deliberately stopped by timeout after completion (exit 124), not a clean exit.
