# Predecessor reconstruction repair

The first 0.1.15 language qualification failed inside the predecessor's exact-map → LOW proof because `tools/spacefox/native_profile.py` in the current checkout had changed after the 0.1.14 release. The same failure reproduced on the unmodified private base. The retained LOW proof requires SHA-256 `71492f1c37bfc044d407fd28257a4d04b30004fa19e11ce9c7c78e53ef357b93`, while the current source is `a0b40cd72fa368b0b1ba55024159ae726fa823aecc0369d3cb4a5490751c7b6e`.

The actual published 0.1.14 predecessor source `1bebd706649176b562681685d33b3cfcc7c9d4dd` contains the exact LOW-proof bytes. The top-level `tools/spacefox/native_profile.py` entry in the retained 0.1.14 export-source ZIP was independently read and matched the same digest and byte content. This change retains those bytes as `prior/tools/spacefox/native_profile.py` and restores them only in the temporary predecessor reconstruction; the new validator checks that their digest matches the immutable LOW proof before doing so. It does not modify the current image pipeline or rewrite a prior receipt. The validator still executes the full predecessor proof and must fail on any other mismatch.
