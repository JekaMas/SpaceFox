# Image pipeline decision and evidence

## Scope and target

Before selecting a change, target at least 20% improvement in a meaningful dominant byte or latency measure for one or more workloads, exact pixels/alpha/identities, ordinary 126,784-byte profile pass, and no material (>5% outside noise) warm redraw regression. A host-only win is not a native claim. Frozen current source-derived map/rocket/site-country pixels and their generator/provenance are in `tests/fixtures/sfr1m-current/README.md`. Other inputs are real retained bundled resources, not current downloadable selections; identities, input and decoded-pixel hashes, sizes and split are in `study.json`. Inputs: 73 map, 54 LOW, 8 rocket and 5 flags. 17 training and 123 held-out identities (the latter include the complete additional inventory); 58 bundled inputs exceed the existing per-raster SFR1 limits and were filtered from that comparison, not counted as supported feed selections. All 140 remain in lossless family comparison. The original small sweep at `/tmp/spacefox-image-study` had duplicate second-generation settings, so its ranking is superseded. The initial standalone CLI import error was a harness failure, documented in PROGRESS; no measurement resulted.

The DP and representation-family comparisons are separate experiments. Rows, exact source hashes, lossless independent reconstruction and host-only timing are retained in `study.json` and `study.csv`. Training ranking selects 1/1; on common encodable examples its held-out map bytes were 1,042,934→1,026,724 (−1.55%, 11 images); LOW 1,460,182→1,417,012 (−2.96%, 51); rocket 7,537→7,517 (−0.27%, 3); flag 446→438 (−1.79%, one). These are serialized SFR1 shard ASCII bytes including headers/base64, not HTTP headers or measured persistent Storage serialization. Current frozen map 36,772→36,211; rocket 1,427→1,423; flag 378→378. The change in tokens would change hashes and can alter map rounding admission, while the gain falls below target, so do not ship it as the winner.

The independent minimum-token-cost row DP explores all legal run/copy lengths with deterministic byte/count tie-breaking; a separately enumerated exhaustive technical-row oracle checks small cases. On the 23 initial assets (`optimal-candidate.json`) the frozen map was 36,772→36,195 (−1.57%), rocket 1,427→1,423, flag 378→378. Its one observed map encode took 1,351.6ms under concurrent host study, versus tens of milliseconds for greedy; these are comparative candidate observations, not a calibrated latency benchmark. It does not justify changed production objects for this modest saving. DP is row-optimal for token bytes, not proven globally optimal for base64, shard boundaries or alternate transport.

For all 140, exact palettes, QOI pixel streams and zlib/raw or row-up predictor were independently reconstructed. No palette conversion is lossy. Current map has 2,380 exact colors, exceeding a 256-entry palette; QOI stream plus estimated standard 22-byte framing 26,538 (base64 estimate 35,384), raw DEFLATE 17,853 (base64 estimate 23,804), compared with SFR1 36,772. Current rocket: SFR1 1,427, QOI file estimate 1,104, zlib 722. Current flag: SFR1 378, QOI file estimate 153, zlib 213. QOI stream encoder and separately written decoder ran against each raster, including exact alpha, but no complete QOI file is emitted; framing and base64 figures are estimates. DEFLATE includes neither a bounded Monkey C decoder nor SFR1-compatible framing/integrity and is not a watch measurement. QOI/DEFLATE would need an explicitly compatible producer/consumer, bounded heap, decode time, transfer, persistent staging/recovery and real SDK qualification before any adoption. The material host-only map compression advantage is real but insufficient by itself to establish an acceptable FR165 runtime.

LOW inputs all have two exact colors. A 390×390 1-bit index plane plus RGB palette is 19,019 analytical bytes for `low-0`, while its actual bundled PNG is 6,114 and SFR1 baseline is 17,514; those are different deployment paths and not comparable GFX allocations. Flags often favor QOI-style runs; small rockets favor zlib or a compact shape-aware path; terrain maps favor filtered/compressed streams in host bytes, but palette limits, decode cost and memory prevent selecting a new native format based on bytes alone. Animation already moves a retained bitmap and LOW already uses a matching bundled outline where available. Vertical rectangle merging, tile dictionaries, deltas, RGB565 and lossy palettes are unimplemented hypotheses: alpha order, fade, quantization and recovery would require separate exact qualification. Compiled resource default packing, PNG packing and phone `makeImageRequest` are distinct platform mechanisms; DynamicResource arbitrary encoded bytes is not documented for FR165. See [25 primary sources](primary-sources.md).

## Selected compatible improvement

Grouping each bounded row into pixel tuples once avoids repeated Python byte slicing while preserving the original greedy decisions and every serialized byte. Nine full-encoder trials per image, before and after in the same checkout and local Python 3.14.7, produced median map 40.475→23.265ms (−42.5%), rocket 1.789→1.249ms (−30.2%), flag 0.0559→0.0533ms. One map and rocket dominate a producer's encoder work, but full package work is dominated elsewhere. Three Starship package trials each: median 4,612.9→4,653.8ms (+0.9%, within observed variation), so no end-to-end speedup is claimed. Each sample's joined shard hashes and complete 106-file closure hash are unchanged (`host-before.json`, `host-after.json`; command `python3 -B openspec/changes/optimize-image-pipeline/evidence/host-benchmark.py`). The tuple allocation is host memory only; watch heap or GFX footprint is unchanged for byte-identical content. Time measurements are not simulator/native/physical/battery measurements.

One bounded cProfile (`package-profile.txt` and `.py`) measured 12.3s instrumented: 16 catalog validations 7.17s cumulative, canonical serialization 6.65s, six rasterizations 0.70s and `_single_profile` 0.63s. Cumulative totals overlap. Profiling overhead is material; don't compare with wall medians. Reusing/skipping catalog validation could affect integrity/ownership and was not justified within this image-local change.

## Proof boundaries and reuse

All 140 resource rasters are independently source-hashed; an exact old-vs-new row-token comparison and separate literal SFR1 decoding cover the selected compatible change. Current offline tests check sourced pixel, role, marker and descriptor identities plus corrupted/truncated refusal; local publisher state checks closure refusal and durable pending state. These are local source observations, not hosted service, phone or physical device tests. The native code and exact current package bytes are unchanged in the matched 106-file sample. Existing ordinary-profile and ACTIVE/LOW signed14 observations apply only at their original input/toolchain boundary: 98 seconds is observation duration, not a decode time. The old functional-source 5,703ms full scene is not an isolated current baseline. The documented FR165 memory figure and previously qualified 126,784-byte profile differ; neither this host study nor existing ACTIVE/LOW evidence establishes physical battery, graphics-pool peaks or a full product green. No current native hotpath changed, so no new native timing or redraw gain is claimed.

The study's initial in-memory memoization key was later strengthened to include dimensions and channel count as well as pixel hash and configuration; a check of this 140-input study found no shared pixel hash with differing dimensions/channels, so the published study's results remain applicable. Cache lifetime is one process and no mutable output is reused across runs.

The older `current-native-scene-whole/current-main-508/current-redraw/receipt.json` predates this work and differs from public base a43e148c in 13 native input files; `decoder-stream-013` NativeSfr and SpaceFoxView snapshots differ as well. Their original receipt bindings have not been changed and do not qualify the current source. The ordinary 126,784-byte marker in `decoder-stream-013/ordinary-diagnostic.log` belongs to its historical functional-source build; its 5,703ms is not a current-source isolated benchmark. The prior `native-feed-bounds/FINAL.md` ordinary-profile observation has a separate bounded feed-admission scope and does not establish complete image decode peak or physical performance. This change did not invalidate a newer current native observation by changing native source, but it does not repair pre-existing native source/receipt drift.
