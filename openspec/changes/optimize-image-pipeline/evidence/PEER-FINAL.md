## Finding and repair

The newly exposed PNG packer used the renderer-specific `png_pixels` reader directly. A complete pixel stream missing IEND could be accepted, and RGB PNG tRNS transparency could be silently dropped. The preexisting parser was intended for pinned renderer output, not arbitrary packer input. The research tool now validates bounded complete chunk structure, ordering, CRC, supported RGB/RGBA mode, compressed stream completion and rejects tRNS while accepting a valid optional RGB/RGBA PLTE; the producer's parser is unchanged. Writes use temporary files and replace each content-addressed shard, then replace the manifest last. Existing output remains authoritative on malformed inputs or a failed manifest replacement; an interrupted write can leave unreferenced immutable shards. Tests cover an actual RGB tRNS PNG, missing/truncated IEND, CRC corruption, trailing data, a valid optional PLTE, existing-manifest preservation, and reference-consumer decoding of CLI shards. A separate injected `os.replace` failure confirmed the previous manifest survives and temporary files are removed (`peer-atomic-probe.log`).
