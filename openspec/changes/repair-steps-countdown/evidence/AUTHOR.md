# Author evidence and limits

The v0.2.17 physical photograph shows a zero step count and absent Body Battery, but does not expose Garmin's returned samples. The established code defect was that built-in steps did not subscribe to the current Garmin steps complication, leaving updates to the existing minute cadence. The old implementation fails the preserved `steps-red.log` test. The current selected-source owner subscribes to ID 2, prefers a valid current Number (including zero), and falls back to the actual ActivityMonitor value only when that complication is unavailable. It neither combines totals nor adds a timer. Custom and built-in use of the same ID shares one read. The callback projects only matching fields; the original new-code unrelated-field failure is retained.

Garmin documents [steps complication values and callbacks](https://developer.garmin.com/connect-iq/api-docs/Toybox/Complications.html), [ActivityMonitor local-day steps](https://developer.garmin.com/connect-iq/api-docs/Toybox/ActivityMonitor/Info.html#steps-var), and [device-dependent Body Battery history intervals](https://developer.garmin.com/connect-iq/api-docs/Toybox/SensorHistory.html#getBodyBatteryHistory-instance_function). The previously authorized, bounded 300-second Body Battery history rule is unchanged: no physical API sample or timestamp is available to establish why the photographed field was absent. In the SDK simulator, the actual Body Battery API returned a non-null iterator and non-null sample with age zero, accepted by that policy (`batch-ninth.log`). This is simulator data, not a physical health reading.

The directed actual-view/renderer selector exercises an ID 2 update of 123 while ActivityMonitor remains zero, zero and null fallback, duplicate-source ordering, hidden/LOW/wake behavior and independent 12-seed/576-event after-each checks. It checks the raw UTC threshold at 86400/86399 seconds, zero, negative and absent targets, plus ACTIVE and shifted LOW vector markers. The 64-seed selected-fitness state model separately passed 3720 events (`fitness-pbt-current.log`). Dots indicate stale only; source hold has its own pause mark and may coexist with a real numeric target. The reschedule mark does not override near/distant color.
