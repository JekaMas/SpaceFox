# Health field and countdown boundary

The 0.2.14 photograph shows the canonical icons and four slots, steps 717, and three dashes with the watch off the wrist. It does not identify the complication or history results actually returned by that watch. The code previously requested steps from `ActivityMonitor` and current health values from Garmin complications 23 (Body Battery), 18 (heart), and 22 (stress), with no history query. The observed defect in the production owner is therefore narrower: valid simulator-supplied SensorHistory was ignored when the current value was missing. Whether Garmin returns suitable history on the physical watch remains unobserved.

| Boundary | Owner and effect | Decision |
| --- | --- | --- |
| Configured roles and subscriptions | `SelectedFields.start`, `ensureSubscriptions`, `readSelected`, `stop` | Default roles select native IDs, custom slots preserve their selected source; failed registration/subscription retries at existing refresh. One provider read per distinct ID. |
| Current and historical values | `SelectedFields`, `HealthSample` | Current built-in Garmin value takes precedence; for Body Battery/stress only, inspect up to three newest history entries and admit the newest valid 0–100 sample at age 0–300 seconds. No history for heart or custom slots. Positive current heart only. Rate-limit history queries by role to one per 60 seconds and retain an accepted sample across a transient empty/error result only within its original TTL. |
| Draw, sleep, resume | `SpaceFoxView.snapshotAt`, `SelectedFields.expireHistory` | Expiry is checked before paint, including first paint after hide; drawing reads no health provider. Stop retains the permitted sample until TTL, not indefinitely. |
| Slot rendering | `Fitness` and scene renderer | Four configured identities remain; absent data is a dash. History does not change art/scene identity. |
| Clock and countdown | `WatchClock`, `SpaceFoxView.snapshotAt`, `CountdownFormat`, `SceneAod.countdownColor` | UTC arithmetic is separate from health. Root's public generation 116 observation reported rescheduled=true, sourceHold=false, stale=false and a four-minute NET shift, consistent with the existing red indication. No color policy change. |
| Scheduling | Existing fitness minute cadence and current view lifecycle timers; `FeedService` background registration | No new timer, background service, network request or persistent health history. |

Garmin's [Complications API](https://developer.garmin.com/connect-iq/api-docs/Toybox/Complications.html), [SensorHistory API](https://developer.garmin.com/connect-iq/api-docs/Toybox/SensorHistory.html) and [SensorSample API](https://developer.garmin.com/connect-iq/api-docs/Toybox/SensorHistory/SensorSample.html) document the relevant types and list FR165/FR165 Music; support does not promise that personal measurements exist. The existing manifest already grants SensorHistory and ComplicationSubscriber. SDK simulation and typed fakes are not physical measurements or proof of on-wrist acquisition.
